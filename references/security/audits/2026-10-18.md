### Verificado OK

- Advisor security: solo `auth_leaked_password_protection` (aceptado). Advisor performance: vacío.
- RLS `true` en todas las tablas de `public` (`games`, `profiles`, `scores`; no hay otras).
- Policies: `games`/`profiles` solo `select`; `scores` `select` + `insert` con `name ~ '^[A-Z0-9_]{1,12}$' and score 0..9999999`. Sin `update`/`delete`.
- Funciones `security definer`: `handle_new_user` (`search_path=""`), `rls_auto_enable` (`search_path=pg_catalog`); ambas sin EXECUTE para `public`/`anon`/`authenticated`.
- Event trigger `ensure_rls` `evtenabled='O'`; trigger `on_auth_user_created` en `auth.users` → `handle_new_user`.
- Constraints: `scores_name_check`, `scores_score_check`, `profiles_username_check` `^[A-Za-z0-9_]{3,12}$`, índice único `lower(username)`; `scores.id` identity `ALWAYS`.
- Extensiones: ninguna en `public` (`uuid-ossp`, `pgcrypto`, `pg_stat_statements` en `extensions`).
- Auth actions: validación servidor de username/email/contraseña (≥8, ≤72, complejidad) en `signUp` y `updatePassword`; login y reset genéricos.
- Callback: `safeNext` correcto; runtime `?next=//evil.com`, `https://evil.com`, `/%5Cevil.com`, `/%09/evil.com` → nunca `Location` externo (y `next` se prefija con `origin`).
- Proxy: `getUser()`, matcher excluye estáticos, cookies propagadas también en redirect.
- `submitScore`: revalida tipos, nombre, rango y existencia del juego. `sendContact`: honeypot, longitudes, email solo `text` (sin HTML), CR/LF eliminados del asunto.
- Headers: los 5 en `/`, `/juegos/asteroides/jugar`, `/auth` (runtime). Sin CSP (aceptado).
- Secretos: solo `NEXT_PUBLIC_SUPABASE_URL`/`_PUBLISHABLE_KEY` públicos; sin `service_role`/`sb_secret`/claves `re_` reales en código ni historial git; `.env*` ignorado salvo `.env.example` (solo placeholders, también en historial).
- Sin `dangerouslySetInnerHTML`, `eval`, `new Function`, `innerHTML` en `app/`, `components/`, `lib/`.
- Logs: sin señal de abuso que lo justifique → no consultados.

### 6.3 DB-PROF-01 — sin email como username

```sql
create or replace function public.handle_new_user()
returns trigger
language plpgsql
security definer
set search_path = ''
as $$
declare
  raw_name  text;
  base      text;
  cand      text;
  suffix    text;
  n         int := 1;
begin
  -- Sin fallback al email: no exponer la parte local en profiles (select público).
  raw_name := coalesce(
    nullif(new.raw_user_meta_data->>'username', ''),
    nullif(new.raw_user_meta_data->>'user_name', ''),
    nullif(new.raw_user_meta_data->>'name', ''),
    'user'
  );

  base := left(regexp_replace(raw_name, '[^A-Za-z0-9_]', '', 'g'), 12);
  if length(base) < 3 then
    base := rpad(base, 3, '_');
  end if;

  cand := base;
  loop
    begin
      insert into public.profiles (id, username) values (new.id, cand);
      exit;
    exception when unique_violation then
      n := n + 1;
      suffix := '_' || n::text;
      cand := left(base, 12 - length(suffix)) || suffix;
    end;
  end loop;

  return new;
end;
$$;

revoke execute on function public.handle_new_user() from public, anon, authenticated;
```
